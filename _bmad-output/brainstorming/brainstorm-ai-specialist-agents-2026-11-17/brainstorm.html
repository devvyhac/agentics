Marketplace Payload Contracts

Bidirectional JSON contract between the Kavver Marketplace webhook dispatcher and the FastAPI agent endpoints. High strictness on schema conformity ensures zero failed settlements.

Input Request (Marketplace → Agent)
POST /webhook 
{
  "id": "req_908a8b11-4f92",
  "match_id": "m_778103-alpha",
  "type": "marketplace_prompt",
  "category": "storyteller",
  "prompt": "Write an evocative opening scene of an orbital salvage dock.",
  "max_words": 250,
  "timeout_seconds": 30
}
Field Type Description
id string (uuid) Unique execution request token.
match_id string Identifier linking prompt to marketplace bid.
type string Operation opcode or prompt classification.
category string Target agent niche (generalist, storytelling, proofreading).
prompt string The raw or formatted task prompt.
max_words integer Strict ceiling for the response body.
timeout_seconds integer Hard upper ceiling before connection drops.
Output Response (Agent → Marketplace)
HTTP 200 OK 
{
  "match_id": "m_778103-alpha",
  "output_text": "Soot and solar flash stained the titanium gantries of dock 9...",
  "word_count": 248,
  "model_tag": "groq/llama-3.3-70b-versatile"
}
Field Type Description
match_id string Must match the incoming payload's match_id identically.
output_text string Sanitized, trimmed, and finalized generated completion.
word_count integer Exact count computed by post-processing logic (≤ max_words).
model_tag string Telemetry tag indicating model provider and version used.

The 4 Core Architectural Pillars

The four non-negotiable architectural foundations agreed during the session to guarantee zero coupling, universal provider portability, and rock-solid production reliability.

1. Kavver NPM Bridge

The external marketplace connectivity, worker daemon, and secure webhook tunnels are handled out-of-band by the Kavver NPM package. Python agents remain pure, simple HTTP web microservices focusing solely on logic.

  • No marketplace websocket pollution in FastAPI
  • Standardized HTTP POST webhook ingestion
  • Decoupled runtime lifecycle and monitoring

2. Universal OpenAI Client

Standardized around the official AsyncOpenAI specification. Switching backends (Groq, NVIDIA NIM, DeepSeek, Together, OpenRouter, or local Ollama) is 100% configuration-driven via per-agent environment variables.

  • Base URL, Model Name & API Key in isolated .env
  • Zero vendor lock-in or specialized SDK dependencies
  • Effortless fallback to local models for offline testing

3. Async Timeout Guards

Internal client-side safety timeouts calculate effective_timeout = timeout_seconds - safety_margin. If an LLM inference lags, the agent gracefully aborts and returns before marketplace cuts the connection.

  • Avoids harsh socket drops and marketplace penalties
  • Graceful fallback responses with partial output
  • Configurable safety margin buffer (default: 2.0s)

4. Strict Word-Count Guard

LLMs frequently hallucinate or exceed requested word limits. Every agent pipeline executes an automated post-processing sanitizer that guarantees output_text ≤ max_words and records the verified word_count.

  • Regex / whitespace tokenizer for exact count
  • Sentence-boundary clipping (no mid-sentence cuts)
  • System prompt calibration + post-hoc guarantee
