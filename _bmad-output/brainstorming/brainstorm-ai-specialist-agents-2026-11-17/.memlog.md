- (direction) Workspace structure: each folder corresponds to an individual agent
- (direction) Sequence: build generalist agent baseline first (all-rounder, writeups), followed by specialists (storytelling, frontend design, proofreading)
- (direction) Deployment: agents exposed to production via distinct endpoints
- (decision) Stance: Creative Partner (trading ideas, probing deeply, pushing past the obvious)
- (technique) started Ecosystem Thinking (biomimetic)
- (direction) Clarification: No swarm or interconnection between agents. Each agent is completely standalone and built separately in its own folder.
- (direction) Marketplace integration model: External agent marketplace registers agent endpoint. Marketplace sends webhook/payload with prompt -> agent endpoint executes prompt -> returns formatted response directly back to marketplace.
- (direction) Priority: Build the generalist agent first for testing purposes as the baseline/template before building specialists.
- (technique) switched to One Feature Only / Standalone Microservice Contract
- (direction) Routing architecture: Single unified server routing to individual agent modules by URL prefix, e.g. /generalist/..., /storyteller/..., /proofreader/... with sub-endpoints like /webhook and /health
- (direction) Marketplace schema registered: Input payload includes id, match_id, type, category, prompt, max_words, timeout_seconds. Output response must match {match_id, output_text, word_count, model_tag}.
- (direction) Configuration requirement: Every agent folder has its own .env.example containing api_key, api_url, model_name, webhook_secret, etc., enabling the user to configure remote model APIs per agent.
- (decision) Framework: Python FastAPI using APIRouters per agent directory
- (decision) Timeout management: Enforce internal async client-side timeouts (e.g. timeout_seconds - safety_margin) to avoid marketplace connection cuts
- (insight) Webhook integration: Kavver npm package handles marketplace connectivity and webhook delivery, so agents focus purely on API endpoint handling
- (decision) LLM Client abstraction: OpenAI-compatible client standard supporting Groq, NVIDIA NIM, DeepSeek, Together, OpenRouter, local Ollama, etc. Configurable via API_KEY, BASE_URL, and MODEL_NAME
- (insight) Word-count strictness: Agents include post-processing logic to ensure output_text complies with max_words and calculate exact word_count
- (insight) Synthesis: High decoupling achieved by standardizing on FastAPI route-mounts + Kavver marketplace payloads + OpenAI-compatible model backends + per-agent .env isolation.
